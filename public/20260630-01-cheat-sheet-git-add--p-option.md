# はじめに

最近、`git add`コマンド実行時に`-p`オプションをつける機会が増えました。

しかし、コマンド実行時提示される選択肢のうち、`y`,`n`,`s`,`?`以外の選択肢をなかなか覚えられずにいます。

また、`?`で選択肢の説明を見れるものの、英語で表示されるため、いまいちよくわからないという問題が発生しているので、
備忘録もといチートシートと題してまとめてみました。

また、おまけとして、ステージ済みの変更を確認する`git diff`コマンドのオプションも記載しています。

他の方の参考になれば幸いです。

# `git add -p`
## `git add -p` の概要
```bash
git add -p
```
`git add -p` を実行すると、複数の修正を行った場合でも、
コミットしたい変更だけを選んでステージングできます。

実行すると、以下のような選択肢が表示されます。
`git add -p`では、Gitが「ひとまとまりの変更（hunk）」ごとにステージングするかを選択できます。

```txt
Stage this hunk [y,n,q,a,d,K,g,/,s,e,p,?]?
```

## `git add -p` の選択肢
各選択肢の意味は以下の通りです。

| 選択肢 | 意味                                   |
| --- | ------------------------------------ |
| `y` | 表示されている変更箇所をステージングする                 |
| `n` | 表示されている変更箇所をステージングしない                |
| `q` | `git add -p` を終了する                   |
| `a` | 現在の変更箇所以降、同じファイル内の残りの変更をすべてステージングする  |
| `d` | 現在の変更箇所以降、同じファイル内の残りの変更をすべてステージングしない |
| `K` | 1つ前の変更箇所に戻る                          |
| `g` | 指定した変更箇所へ移動する                        |
| `/` | 正規表現で変更箇所を検索する                       |
| `s` | 表示されている変更箇所をさらに細かく分割する               |
| `e` | 表示されている変更箇所を手動で編集してステージングする          |
| `p` | 現在の変更箇所を再表示する                        |
| `?` | ヘルプを表示する                             |

## 覚えていくと便利な選択肢
最初のうちは、以下の4つを覚えておけば十分だと思います。

| 選択肢 | 意味              |
| --- | --------------- |
| `y` | ステージングする        |
| `n` | ステージングしない       |
| `s` | 変更箇所をさらに細かく分割する |
| `q` | 終了する            |

特に `s` は便利です。

1つの変更箇所として表示されている中に、

* 今回コミットしたい変更
* 今回コミットしたくない変更

が混ざっている場合、`s` を使うことで変更箇所をさらに分割できることがあります。

# git diff
## ステージング済みの変更だけを確認する

`git add -p` でステージングしたあと、ステージング済みの変更だけを確認したい場合は、以下のコマンドを使います。

```bash
git diff --staged
```

また、以下のコマンドでも同じ内容を確認できます。

```bash
git diff --cached
```

一方で、まだステージングしていない変更を確認する場合は、通常の `git diff` を使います。

```bash
git diff
```

つまり、確認したい内容ごとに使い分けると以下のようになります。

| コマンド                | 確認できる内容         |
| ------------------- | --------------- |
| `git diff`          | まだステージングしていない変更 |
| `git diff --staged` | ステージング済みの変更     |
| `git diff --cached` | ステージング済みの変更     |

個人的には、ステージング済みの変更を確認する場合は `git diff --staged` の方が意味がわかりやすいと思います。
